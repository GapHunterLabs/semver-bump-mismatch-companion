Reports a release in CHANGELOG.md (Keep a Changelog format) that describes a breaking change but only bumps the MINOR or PATCH version compared with the release right before it. SemVer expects a MAJOR bump for a breaking change.

A release counts as breaking when its entry contains the word BREAKING (not negated, so "non-breaking" or "no breaking changes" do not count) or a ### Removed section.

Example: ## [1.5.0] says "BREAKING: renamed chargeCustomer()" and the previous release is 1.4.2. The fix is to release it as 2.0.0.

Releases on a 0.x version are not checked: SemVer allows breaking changes before 1.0.0.
